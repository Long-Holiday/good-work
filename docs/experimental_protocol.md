# DiffPeak-SAM 实验协议：公平比较与 RTX 3090 24GB 训练

本文规定后续主模型、消融及主流模型比较的统一口径。协议状态为**待预实验冻结**，不是训练结果。`configs/3090.yaml` 是配置起点；本文不声称已在 RTX 3090 上测得显存、吞吐或精度。

核心约定：**固定数据、信息来源、评估及预算规则；允许各模型使用适合自身的实现优化，但必须披露资源成本。** 公平不等于把所有模型的学习率、micro-batch 和优化器强行设成一样。

建议执行顺序：

1. 冻结 train/val/test，补齐统一自动评估和随机数控制。
2. 用开发种子 `2026` 在真实 3090 上测全尺寸 A/B/C/D，先确认稳定性和整轮成本。
3. 用相等开发预算确定各方法超参、阶段长度与计算上限，填写登记表并冻结。
4. 按 42/43/44 运行主模型、基线及核心消融，共享不受消融影响的阶段前缀。
5. 全部模型选定后统一评估 test，报告精度、种子波动和包含全部阶段的资源成本。

## 1. 实验分层与可以支持的结论

| 实验层 | 固定条件 | 允许变化 | 可支持的结论 |
|---|---|---|---|
| 主流自动分割比较 | 划分、训练标注、输入视野、评估器、测试预算及调参机会 | 模型、适合模型的优化器和学习率；公开预训练权重须披露 | 在相同任务协议下的系统表现；预训练不同，不单独归因于架构 |
| 机制消融 | 同种子父 checkpoint、预训练、数据顺序规则、训练预算、非目标超参及推理协议 | 一个预先声明的因素 | 该因素在本设置下的贡献 |
| 资源预算比较 | 同一张 3090、相同计时边界、相同 GPU 小时上限 | 各方法在预算内的训练分配 | 给定硬件预算下的精度与效率 |
| 提示诊断 | 同一模型、同一评估集 | 真值提示、删除或打乱提示 | 提示依赖性及上限诊断；不进入自动分割主表 |

主表和资源预算表分别报告。不能把“相同 epoch”“相同 optimizer step”或“相同 GPU 小时”中的任意一个单独称为所有方面都公平。

同一 SAM ViT-B 预训练权重、同一编码器冻结方式下的确定性自动提示模型，是控制预训练信息最直接的基线。ImageNet 初始化的 CNN/Transformer 与 SAM 预训练模型可以比较，但表格中必须列出预训练来源、额外数据、冻结范围和可训练参数。若主张排除预训练影响，需要另外设计匹配预训练的对照，不能仅靠使用同一训练集实现。

## 2. 数据：先冻结独立测试集

### 2.1 主协议

- 数据源：本地 DeepGlobe Road 中有标注的原始影像；README 记录为 6,226 对，正式建清单时重新核实数量、配对及损坏文件。
- 建议一次性划分为 train/val/test 约 80%/10%/10%；若核实为 6,226 对，可采用 **4,980 / 623 / 623**。
- 划分种子固定为 `42`；训练种子另行变化。所有模型、所有训练种子使用完全相同的划分文件。
- 优先按地区、原始大图或重叠来源分组后划分；当前 metadata 不含地理/场景分组，不能声称已实现地区隔离。有外部分组信息时，比例可近似，组隔离优先于精确张数。若只能随机按原图划分，论文中明确这是内部随机划分，地理独立性未保证。
- 先划分原图，再裁块、增强、缓存和采样；同源/重复/重叠影像不能跨集合。可用文件哈希排查完全重复，近重复及地理重叠需要额外检查。
- 官方无标注 `valid/`、`test/` 仅作推理或官方提交；不可计算本地监督指标，也不用于提示监督、奖励、归一化拟合或模型选择。

**当前实现限制：** `scripts/prepare_splits.py` 只创建有标注 train/val 及无标注清单，不直接生成上述三分划分；不能假设已有 `--test-fraction` 参数。正式实验前需补充划分工具或生成兼容数据读取器的第三份有标注清单，保存于新的版本目录，例如 `splits/protocol_v1/`，不要覆盖旧清单。模型训练只读取 train/val，test 通过最终评估入口单独加载。

如果旧验证集已被用于大量方法选择，应保留其验证用途，从尚未被用于任何训练/调参的数据中建立测试集；若没有这样的数据，须重新建立独立测试来源。不能把已参与训练的样本重新命名为测试集。

### 2.2 归档与使用权限

冻结前保存原始影像 ID、划分文件 SHA-256、样本数、标注版本、分组依据、预处理版本及重复检查结果。所有模型共用同一份文件。

- train：梯度、训练提示、GRPO 奖励、增强及困难负样本挖掘。
- val：预实验、有限超参搜索、阈值校准和 checkpoint 选择。
- test：协议冻结、全部模型选择完成后，按预注册运行列表统一评估；不得据此挑种子、阈值、模型或增加采样次数。

如果查看测试结果后修改方法，应将其明确记为新的实验轮次；不能继续把同一测试集当作完全未见数据。

## 3. 输入、监督与自动推理

### 3.1 统一信息与图像几何

- 主比较使用 RGB、同一原始影像视野、最长边缩放至 1024、右下填充，最终恢复至原始标注尺寸评估。标签使用最近邻变换；评估排除 padding。训练损失排除 padding 是跨尺寸协议要求，当前训练损失尚未普遍实现有效区域屏蔽；本数据需先确认所有使用影像为 1024×1024，此时无实际 padding。若引入非方形或其他尺寸，先补有效区损失，再开展正式比较。
- 道路标签二值化规则统一。正负采点距离使用原始标注像素，热图高斯及 NMS 使用热图像素，不能混用单位。
- 所有可训练模型采用同一组已经实现并核实的几何增强和概率；额外颜色增强、多尺度训练、随机裁块等作为独立实验，不能只给一种方法使用后混入主表。训练样本、几何增强及监督布局的随机性尽可能分别按训练种子/epoch/样本 ID 派生，避免不同分支因额外采样消耗 RNG 而连带改变其余训练输入；相同全局 seed 本身不保证分支数据完全配对。
- 各预训练骨干使用其规定的输入归一化；统一可见图像内容比强制相同归一化更合理。SAM 保持现有 RGB `[0,1]` 接口，由封装内部归一化。
- DiffPeak-SAM 热图为 `2×256×256`，SAM 使用 ViT-B。修改输入尺寸、热图尺寸、负点通道或提示预算属于实验因素；现有 1024/256 几何在引擎和模型中固定，更改尺寸需要修改模型/几何代码，不能仅写一个新 YAML 键。
- 训练真值提示、热图标签、骨架监督和奖励都只能来自 train 标注。验证真值提示只在独立诊断轨道使用。

### 3.2 自动推理主协议

每张影像一次自动预测，不使用人工或真值点/框，不用测试标注选轨迹。固定：

| 项目 | 主协议起点 |
|---|---|
| 扩散训练时间步 | 1,000 |
| 推理采样步数 | 20 |
| 每图候选数 | 1 |
| 转移标准差下限 | 0.02 |
| 热图后处理 | sigma=0.5，h=0.05，threshold=0.3，NMS 距离=4 热图像素 |
| 分割阈值 | 0.5 |
| TTA / 集成 | 关闭 |
| 峰数 | 可变，不加隐藏 top-k；报告正负点数和长尾 |
| 无正峰 | 按当前模型规则输出空掩码 |

若要对分割阈值进行校准，所有方法使用同一预声明候选网格和验证机会，并把该表与固定 0.5 的主表区分；峰值阈值与分割阈值是不同参数。分割阈值也参与 D 的训练奖励，须在 D 前冻结；D 后改阈值只作显式的后处理补充实验，不能称训练/奖励协议等价。峰值协议影响 A/C/D 提示，须在 A 前冻结；若中途改变，重训所有受影响阶段。热图构造参数改变会进一步影响 B，须从最早受影响阶段重训。

固定推理随机数方案：为每个样本 ID 从固定评估种子派生可复现种子，或显式传入独立的随机数生成器；采用稳定哈希，不能使用跨进程变化的 Python `hash()`。不同模型、checkpoint、batch size、样本读取顺序不能改变某个样本对应的评估随机输入。不能从多个随机预测中挑最好的一次进入主表。

**现有实现与补齐条件：** `evaluation_seed` 已按稳定样本 ID 派生局部 generator，独立评估也已提供 `--seed`；最终评估统一显式使用 `--seed 2024`。引擎验证固定 batch=1，但基础种子目前取训练 seed，因此还需把训练验证的评估基础种子独立为固定值 2024；仅在 YAML 写一个未知 `evaluation.seed` 不会自动生效。保留验证 batch=1，若改批量验证须实现逐样本 generator。现有默认验证通过局部 generator 隔离扩散 RNG，仍应做调用前后 RNG 状态及重复输出检查。固定 generator 不等于所有 CUDA 算子逐位确定，确定性后端策略另行冻结。额外随机重复仅用于波动分析，必须列出总推理成本。

多步数、TTA、多个候选或多次采样平均放入独立的精度—耗时实验；各模型都获得同样声明的测试扩展机会，不计入单次主表。

## 4. 训练预算与模型选择

### 4.1 DiffPeak-SAM 起始计划

沿用现有可解释的四阶段起点，预实验后一次性冻结；不要在看到测试成绩后改变阶段长度。

| 阶段 | 可更新部分 | epochs | 初始 LR | 有效批次及主要监督 |
|---|---|---:|---:|---|
| A | SAM mask decoder | 15 | 1e-4 | A/B/C micro-batch=1，累积=4；真值提示分割 |
| B | 条件模块与去噪 U-Net | 60 | 1e-4 | 扩散 MSE、热图及辅助监督 |
| C | SAM mask decoder | 10 | 5e-5 | 冻结生成提示下的分割监督 |
| D | 去噪 U-Net | 10 | 1e-6 | 同图 GRPO，G=4；不是监督有效 batch=4 |

共 95 个训练集遍历，A/B/C 为 85 次，D 为 10 次。图像/提示编码器始终冻结；D 的条件模块和 SAM 冻结，参考 U-Net 固定。A/B/C 使用全局 warmup 比例 0.05、LR floor 比例 0.05；D 两项为 0.1/0.1，沿用当前 warmup + cosine 调度。

D 起点：`group_size=4`、`update_epochs=1`、`ppo_clip=1e-4`、`kl_weight=0.01`、`anchor_weight=0`、`advantage_std_delta=1e-4`、`point_cost_warmup_steps=100`、`amp_init_scale=64`。奖励使用 `0.6×IoU+0.4×clDice−0.05×(Kpos+Kneg)/32`。不更改联合动作 log-prob 求和语义来换取表面稳定性。

D 开发验收先观察前 100–300 组：组内奖励标准差、零优势比例、正负峰数、实际更新/AMP 跳步、联合 log-ratio、KL 和裁剪比例。固定周期比较自动提示验证 macro IoU/clDice 与 C 父模型。若始终无实际更新或出现非有限值，先排查实现和数值，不直接投入 10 轮×3 种子。若仅没有验证增益，不能断言实现错误；保留不改善的结果，并在开发阶段按同等调参预算决定是否继续。

预算登记至少区分：原图展示次数、监督 optimizer update、D 已处理组数、有非零策略优势的组数、实际 optimizer step、轨迹数、轨迹转移数及 GPU 小时。**零优势不等于无更新：** 默认 KL 非零时，常量奖励组仍可能通过 KL 执行 optimizer step；KL 和 anchor 都为 0 时才可能整组跳过。AMP 跳步不算实际更新。A/C 无有效提示时也可能跳过反传，计划更新数不等于实际值。记录各项与调度进度；100 组点成本预热按已处理组数推进，在 4,980 张训练集上约占首轮 2%，不是长期预热。

例如 N_train=4,980、A/B/C batch=1、累积=4 时，每轮计划约 `ceil(4980/4)=1,245` 次更新，是否因 AMP 跳步减少需另记。D 每轮 4,980 个图像组，10 轮共 49,800 组、199,200 条轨迹、3,984,000 次采样转移；默认 KL 开启时另有约 3,984,000 次当前策略重放前向及 3,984,000 次参考 U-Net 前向，合计约 **11,952,000 次 U-Net 前向**，另加重放反传及检查点重算、SAM 奖励和 CPU 后处理，不能直接换算小时。上述数值只对应新建的 4,980 张 train；现有 5,603/623 开发划分不可混用。

### 4.2 主流模型的预算与调参

建议第一批覆盖：U-Net、DeepLabV3+、道路专用 D-LinkNet，以及 SegFormer-B2；模型实现、backbone 和预训练版本必须记录。它们尚不是本仓库已接入的基线。预算有限时先完成每种范式一个代表，后续再增加模型，不能只选本方法容易胜出的旧配置。

采用两个互补视角：

1. **数据曝光受控主表：** 每次正式训练允许最多 95 次训练集完整遍历，不含验证；DiffPeak 按上表分配，直接分割模型在相同上限内用验证选择 checkpoint。每种方法获得同样的调参次数和验证机会。报告实际曝光量及计算成本。各方法不同目标和预训练的差异仍须披露，该表不声称计算量相同。
2. **等计算补充表：** 通过 3090 预实验确定一个可承受的统一 GPU 小时上限 H，冻结 H、验证/保存频率与预算计时边界。各方法在 H 内运行并只从预算内已评估的 checkpoint 中选择。H 必须在主实验前写入登记表，不能根据测试表现指定。H 至少容纳预注册的完整 A/B/C/D 最小计划；若预算导致只完成 C，须标为截断变体，不能称完整模型。提前完成计划的方法是否可在剩余 H 内延训，也须统一预注册；额外调参仍计入开发预算。单卡运行时，建议以独占该卡的训练进程墙钟计入 GPU 小时，包含数据等待、验证和保存；纯 CUDA 内核活动时间另列。这样 CPU 峰值处理或轨迹传输造成的闲置也会计入资源占用。

调参起点：每种模型最多 **3 个候选配置 × 1 个开发训练种子**，均在相同较小预算内筛选；每个候选改变什么、看过哪些验证结果都记录。只用同等筛选预算会漏掉某模型合适学习率，因此候选应参考相应实现的合理范围，而非所有模型套相同 LR。若仍未收敛，主表标明预算限制，再在所有方法可获同等机会的独立充分训练设置中补充。

最终固定配置后使用训练种子 **42、43、44**；训练数据划分不随训练种子变化。资源允许增加至 5 种子时，所有主表方法同等扩展。不能只补跑本方法或只保留最好种子。

### 4.3 验证与 checkpoint

- 全部方法按相同数据曝光间隔做完整验证，建议每 5 次遍历一次并包括最终轮，正式训练 YAML 显式设 `train.val_every: 5`；按验证集 **macro IoU** 选择，平局取较早 checkpoint。额外稀疏验证不得只给某个方法挑模型。完整 M0 的最终候选来自 D 的预定验证点，C 作为 A1 单独报告；若允许“D 不改善就回退 C”，应预先定义为另一套选择规则，不能事后回退掩盖后训练退化。
- A 的真值提示验证用于阶段内 GT-prompt macro IoU 选模，并单独标为受提示监督指标；B/C/D 选择使用自动提示验证。A 不进入自动分割排名。父 checkpoint SHA-256 目前需外部登记，训练日志未自动完成父文件哈希归档。
- 每阶段使用独立输出目录；保留 `best.pt`、末轮快照、选中 epoch 及父 checkpoint SHA-256。建议分阶段训练，并用该阶段预先规定的 best 初始化下一阶段。固定曝光主表中，候选计划每 5 轮验证一次对应 A/B/C/D 共 3+12+2+2=19 次检查，与直接分割模型 95 轮内的名义检查次数一致；但 A 使用真值提示、各阶段逐次选择仍不同于单模型的 19 个自动分割候选，不能声称统计选择能力严格等价。开发调参与正式验证次数分别登记，必要时增加阶段末轮固定串联的敏感性检查。若调整阶段长度，应同步重新核对验证机会，不能因阶段末轮额外检查获得隐含的选模优势。
- 当前 `--stage all` 按阶段末轮权重串联，不自动按每阶段 best 串联。若采用本文 best 协议，必须分阶段运行。不能在不同实验中混用末轮和 best。预算计入每阶段实际执行的全部训练，即使最终 best 来自较早 epoch，也不能从成本中扣除已执行但未被选中的尾部训练。
- 不在固定预算主表提前终止表现较差的正式运行；数值失败可以终止，登记原因、已用资源及重跑情况。预算内 best 已允许选择较早 checkpoint。
- 训练中的验证需隔离 RNG，不能因验证频率改变后续训练采样；固定验证随机输入，避免把更幸运的扩散采样选成更优模型。此处须先核实现有引擎行为。

## 5. 消融：优先回答哪些问题

除显式改变前缀的 A5/A6/A7/A8 外，D 配方消融从**同一种子、同一个 C checkpoint**出发，使用同一参考策略、组大小、采样、调度、验证样本及推理随机数方案；被消融的字段除外。共享前缀允许省算力，但只能在确实没有改变前缀训练定义时复用。

| 编号 | 实验 | 改变内容 | 需重训起点 | 优先级及解释 |
|---|---|---|---|---|
| M0 | 完整 A+B+C+D | 基准 | A | 主模型 |
| A1 | 无 GRPO：A+B+C | 去掉 D | 复用 C | 必做；说明 D 的总增益，但额外训练预算也减少 |
| A2 | 等额外曝光的监督延训 | 用 10 轮监督 U-Net 延训替代 D，冻结范围与 D 一致 | C | 必做；区分 GRPO 与“多训练 10 轮”，需新增训练入口 |
| A3 | 无点数成本 | `reward.point_cost=0` | C→D | 必做；其余质量权重不变 |
| A4 | 无 KL | `rl.kl_weight=0` | C→D | 建议；常量奖励组可能转为跳过，须记录实际步数及调度差异；解释为移除 KL 的系统影响 |
| A5 | 无 C 适配 | B 后直接 D，与完整模型控制 D 预算 | B | 建议；缺少 C 的差异同时含少训练，可补等预算版本 |
| A6 | 正点单通道/不使用负点 | 监督、生成、提取与训练提示一致修改 | 至少从最早受影响阶段 | 结构消融；仅在推理删负点是诊断，不能替代重训 |
| A7 | 确定性 CNN 热图 + 同款 SAM | 相同 SAM 预训练及解码适配，替换扩散生成器 | 对应生成器及适配阶段 | 重要外部基线；需实现，不能称为已有开关 |
| A8 | 普通局部极大替代 h-maxima | 已有 `peaks.h=0` 路径；校准机会相同 | A 及所有依赖它的阶段 | 可选；提取器也影响 A 的真值提示，不能只在 D 后替换 |
| A9 | 点成本预热 0 vs 100 | 仅预热 | C→D | 可选稳定性分析 |
| A10 | G=2/4/8、步数=10/20/40 | 分别单因素变化 | 视训练/推理实验定义 | 固定组数时轨迹成本不同；固定轨迹数时更新数不同，两种口径分别登记；步数扫描单独做 |

A2 不能直接通过 `--stage B` 完成：B 会更新条件模块，目标和冻结范围均不等于“只监督延训 U-Net”。需要显式实现监督控制，固定条件/SAM/参考初始化，并保持 10 次数据曝光。它仍不等于计算匹配；必要时增加按 H 匹配的监督控制。单纯“额外跑 GRPO 但不更新”只控制运行成本，不能替代额外监督优化对照。

预算顺序：先用独立开发种子（建议 `2026`）完成缩短预算的 M0/A1/A2/A3 及基线可运行性检查，再冻结；正式主表和核心消融使用 42/43/44。开发运行不混入正式均值。其余探索可先单种子，但明确标为探索性，不据此作稳定性结论。

共享 A/B/C 前缀减少的是**本轮实验总开销**。单个完整方法的成本报告仍包括其 A/B/C，不能只给本方法报 D 的增量时间，却给基线报从头训练时间。

## 6. 在 24GB RTX 3090 上提高效率

### 6.1 优先使用不改变实验定义的措施

| 措施 | 采用规则 | 当前状态 |
|---|---|---|
| 冻结 SAM 图像/提示编码器 | 保持冻结并避免保存无用梯度；同图尽量复用已计算特征 | 已有基础实现，具体复用范围以代码为准 |
| AMP | 先沿用 `train.amp=true`；GRPO 的 log-prob、ratio、优势和 KL 保留稳定精度路径 | 已有；正式卡需验证数值行为 |
| U-Net 激活检查点 | `model.gradient_checkpointing=true` 为保守起点；显存充足时测量关闭是否更快 | 已有；重算换显存，不保证一定提速 |
| 梯度累积 | 主协议 A/B/C 固定 batch=1、accumulation=4；2×2 仅作独立系统实验 | 已有；C/D 噪声依赖批次组成，不能视为等价替换 |
| D 轨迹 | G=4 串行 rollout、轨迹暂存 CPU，保持组内标准化及重放定义 | 已有；不把监督累积参数套用为 D 的有效 batch |
| CPU 数据处理 | 开发期测 workers=2/4/8，主协议固定选定值，默认起点为 4；使用本地 SSD | worker ID 参与现有数据 RNG，因此数量变化会改变增强/提示随机流 |
| 调整日志频率 | 保留必要诊断，避免每条轨迹写图片或频繁完整保存 | 已有 `logging.log_every`；测量写盘成本 |
| 分支复用 | 同种子不受因素影响的 A/B/C checkpoint 复用 | 可按分阶段 CLI 组织 |

当前 CUDA autocast 明确使用 FP16，尚无 BF16 类型开关；`amp_dtype: bf16` 等未知 YAML 键可能被静默忽略，不能当成可用参数。配置须对照实际读取字段，正式工具宜加入未知键校验。记录 `train.deterministic`、cuDNN 确定性/benchmark 及 TF32 实际状态；即使启用当前 deterministic 路径，其 warn-only 行为也不代表逐位确定性已保证。3090 的 BF16、TF32、channels-last、`torch.compile`、高效注意力等需逐项确认算子/实现支持与收益，新增入口后才可写为可运行配置，不能靠向 YAML 添加未知键实现。

TF32 及低精度开关会影响数值；须记录并对所有方法采用一致准则。启用前做固定样本精度与数值检查。`torch.compile` 的首次编译时间单列，同时报告包含编译的总训练时间；不能排除本方法编译开销却计入基线启动成本。

**离线特征缓存有条件使用：** 冻结 SAM 的特征可以缓存，但 RGB 变换、padding、归一化、权重版本和精度必须一致。经过翻转/旋转后的图像应重新编码或使用对应增强版本的缓存；不能假设直接翻转/旋转 SAM embedding 等价。可训练条件模块不能预先缓存后仍声称在训练它。单份 `256×64×64` FP16 embedding 约 2 MiB，6,226 张约 12.2 GiB，仅为特征本身，未计多增强版本、索引和其他数据。缓存实现及增强策略若改变，需独立登记。D 的 CPU clDice 会反复对预测和标签求骨架，可考虑缓存每个实际增强版本的目标骨架；骨架化一般不与翻转/旋转严格交换，不能把单份骨架变换后宣称等价。缓存优化先核实奖励逐值一致性，不能省掉预测骨架化或改变 clDice 定义。

### 6.2 目标卡预实验

在正式训练前用真实 SAM ViT-B 权重、完整 1024 输入、256 热图和代表性稠密提示样本测试；缩小到 128 输入的 smoke 不能替代显存验收。

1. 固定一个仅从 train 取出的代表性子集，例如 128 张，保存为独立临时 manifest；当前 `train.py` 没有训练 `--limit` 或 `--max-groups` 参数，精确截取批次需要测量工具。子集只用于稳定性和吞吐，不把它的分数当正式结果。`check_targets.py --samples` 只取前 N 张，不等于代表性抽样。
2. A/B/C 分别预热 10 个 micro-batch，测至少 50 个 micro-batch；D 纯吞吐测量先预热 5 组、测至少 20 组。正式 D 数值行为检查须超过 100 组预热，建议覆盖 100–300 组并区分预热/稳态；若只为计时关闭点成本预热，明确该设置不用于效果验收。覆盖 reward 有差异、零优势及较多峰的样本。小样本不能证明显存长尾安全，正式训练继续监控。
3. 每个候选配置记录：阶段、batch/累积、G/步数、峰数分布、images/s 或 groups/s、单更新耗时、CPU RAM、allocated/reserved 峰值、验证耗时、写盘耗时、AMP 跳步和非有限值。
4. 独占同一 GPU，固定功耗/时钟策略并记录温度、功耗与其他进程；通过 CUDA 同步确定 GPU 工作结束再计时。分别记录纯训练区间和包含数据/验证/保存的总墙钟时间。
5. 主实验固定 1×4。2×2 可单独测吞吐，但当前 C/D 的 generator 依赖整批 ID、A/C 有无有效提示会影响样本权重，因此并非只有舍入误差。若正式采用，作为独立系统配置并重新做相关种子。D 强制 batch=1；训练 batch 字段是全阶段共享值，若不同阶段需要不同值必须使用各自完整 YAML。D batch>1 会改变按 loader batch 推进的组数、预热和调度，不能套用本文逐图预算。
6. 显存有余量时，对 B/D 单独比较检查点开/关。D 单图串行组不因增大监督 batch 自动提速，应优先查采样、参考重算、CPU 峰值处理和 SAM 奖励耗时。
7. 选择持续吞吐更好的稳定配置后冻结；建议为显存长尾留 2–4 GiB 余量，约 20–22 GiB 的总占用只作调优参考，不作验收承诺。allocated/reserved 不等于 `nvidia-smi` 总占用。

验收关注：有限损失/梯度、可观察到的实际参数更新、可恢复的 checkpoint、固定评估可复现、GPU/CPU 内存无持续增长、端到端吞吐稳定。高显存占用或瞬时 GPU 利用率本身不代表训练高效。

**OOM 处理顺序：** 清查意外解冻/保留图 → 保留 AMP 与检查点 → 在支持的阶段降低 micro-batch 并相应调整累积 → 清理不必要 GPU 常驻对象/改进串行重放。减少 workers 主要缓解主存压力。改变 G、采样步数、分辨率、峰数上限或可训练模块会改变实验因素，必须另立配置并重做相关对照，不能只给 OOM 的模型悄悄降配。

若仍无法在 24GB 内完成某个基线，应报告该设置 OOM，或为所有相关方法建立一致的较小分辨率/裁块补充轨道；不可把不同视野/分辨率下的成绩混成严格同设置主表。

### 6.3 排期与时间估算

先完成预实验再承诺训练天数。**95 次遍历是沿用现有配置的候选起点，不是必须花满的预算。** 开发阶段可用较短的 B/D 试跑判断收敛与成本，例如先看 D 的前 1–3 轮；随后根据验证收益与预计总 GPU 小时，一次性缩短并冻结正式阶段长度。若将 D 从 10 轮改为 E_D，监督延训对照、总数据曝光上限、调度总更新步数及成本估计同步改为对应值，不能只缩短本方法的部分分支，或中途 `--resume` 改 epoch 预算后仍声称原定曲线。不要先启动三种子的 95 轮全实验，再根据资源耗尽临时截断。

设每阶段一次遍历的训练墙钟时间为 t_A、t_B、t_C、t_D，则现有候选计划一个种子的基础估计为：

`T_full ≈ 15t_A + 60t_B + 10t_C + 10t_D + 验证 + 保存 + 启动/编译`。

这里 t_A 等表示**排除验证和保存的纯训练区间墙钟时间**。现有日志 `epoch_seconds` 包含验证及部分日志、但不含后续 checkpoint 保存，不能直接代入后再加一次验证；需外部测量或新增分项计时。reserved 峰值、CPU RSS、推理 P50/P95 及分项吞吐也尚无完整内置统计，应通过统一测量工具补齐。记录测量子集如何外推，并用完整一轮校正；D 的峰数长尾、CPU/GPU 传输及零优势比例会使简单线性估计偏差。3 种子按顺序独占一张卡运行，避免多个重训练进程抢占显存和污染计时；只有实测更快且满足同一资源口径时才考虑并行。

## 7. 评价、统计与效率报告

### 7.1 指标口径

- checkpoint 选择指标固定为验证 macro IoU；主表同时给出 **macro IoU、micro IoU、F1、clDice**，F1 明确 macro/micro，不能互换。
- macro 为逐图得分等权平均；micro 先累加所有 TP/FP/FN 再算指标。多种子统计在每个种子的全测试集指标上计算。
- 主评估在恢复后的原始影像尺寸进行。连续概率先按统一插值规则恢复，再阈值化；标签不做双线性插值。现有评估器是否符合该规则须单独核实。若在原图监督和奖励前已恢复连续预测，loss/reward/选模均应遵循同一约定；若另用模型网格作训练代理，必须明确代理与最终指标的分辨率差别，所有模型的最终评估仍统一。
- 空预测且空标签质量得分为 1，仅一方为空为 0；报告无道路影像比例。F1 与 IoU 空图规则在各模型间一致。
- clDice 使用二值预测/标签的骨架；训练 soft-clDice 不当作最终 clDice 数值。
- 拓扑路径代理与正式 APLS 分开。当前双向路径代理不是 APLS；若引入正式 APLS，需统一图构建、简化、节点匹配和单位，并冻结实现版本。
- 全量 test，禁止用 `--limit` 或挑图生成主表。保存逐图指标、预测、样本 ID 与失败记录，以便复核。当前有标注评估遇错会中止，不允许跳过失败图后报子集均值；外部登记失败及重跑。评估输出另附命令、代码/依赖、checkpoint 和 split 哈希，现有训练 session 元数据不会自动完整复制到评估结果。官方无标注提交还需核对预期 ID 和输出数量完全一致。

### 7.2 种子、配对与失败

报告 3 个训练种子的均值±样本标准差，并公开各次结果。机制消融按训练种子配对计算 `ΔIoU` / `ΔclDice`；共享父模型使实验相关是设计的一部分，不把这些分支当独立模型重复。

如给出 95% 置信区间，说明重采样单位：逐图配对 bootstrap 反映测试样本不确定性，不能代替训练种子不确定性；有地区分组时按组重采样。3 个种子不足以支持很强的显著性断言，多消融比较需说明多重比较或将结论保持为描述性。

固定失败处理：记录 NaN/OOM/中断原因及已用资源；同一软件缺陷修复后对受影响方法采用同一规则重跑。不能反复重跑到某个方法出现较好种子才停。
